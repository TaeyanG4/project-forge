# project-forge

프리랜스 개발 스튜디오 **FORGE** 의 웹사이트와 제품 데모 모음.

빌드 도구도 패키지 매니저도 쓰지 않습니다. 파일을 브라우저로 열면 그대로 동작하고,
저장소를 그대로 올리면 그대로 배포됩니다.

| 페이지 | 파일 | 내용 |
| --- | --- | --- |
| 메인 | `site/index.html` | 스튜디오 소개, 대표 작업물, 예상 견적, 견적 문의 |
| 견본실 | `site/gallery.html` | 작업물을 분야별로 모아 보는 곳 |
| PALLET | `site/pallet.html` | 재고 관리 SaaS 제품 데모 (작업물 예시) |

---

## 실행

서버가 필요 없습니다. `site/index.html` 을 브라우저로 열면 됩니다.

일부 브라우저는 `file://` 에서 로컬 저장소 접근을 막으므로, 밝기 전환 기억 같은
사소한 기능을 확인하려면 간단한 정적 서버를 띄우는 편이 낫습니다.

```bash
cd site && python -m http.server 8000
```

## 내용 고치기

작업 목록과 연락처는 각 HTML 안의 `<script type="application/json" id="site-data">`
블록에 들어 있습니다. 직접 고쳐도 되지만, 편집기를 쓰면 실수가 줄어듭니다.

1. `site/admin.html` 을 **크롬이나 엣지**로 엽니다 (로컬 전용, 저장소에 없음 — 아래 참고)
2. `사이트 파일 연결` → `site/index.html` 과 `site/gallery.html` 을 고릅니다.
   한 번만 하면 기억하고, 지금 사이트에 들어 있는 내용을 읽어 옵니다.
3. 작업 추가·삭제·순서 변경, 연락처 수정. 카드 미리보기가 옆에서 같이 바뀝니다.
4. `사이트에 바로 반영` — 두 파일이 함께 갱신됩니다.
5. 공개하려면 `git add -A && git commit -m "견본 등록" && git push`

> **반영은 내 컴퓨터의 파일까지입니다.** 공개된 사이트는 push 해야 바뀝니다.

`index.html` 과 `gallery.html` 은 같은 데이터를 봐야 목록이 어긋나지 않으므로
편집기가 항상 두 파일을 동시에 씁니다.

### 파이어폭스·사파리에서는

직접 쓰기(File System Access API)를 지원하지 않습니다. 예전 방식을 쓰세요.

1. `파일로 저장` → `site-data.json`
2. `cd site && python apply.py` — 두 파일에 함께 넣고 각 파일 옆에 `.bak` 을 남깁니다

### 실수로 덮어쓰지 않도록

편집기 안의 기본값은 만들 때 찍어 둔 스냅샷이고, 편집 중이던 내용은 브라우저에
남습니다. 둘 다 사이트보다 낡아 있을 수 있어서, 파일을 연결하거나 편집기가 갱신되면
어느 쪽을 쓸지 물어봅니다. 언제든 `사이트에서 읽어오기` 로 현재 내용을 가져올 수 있습니다.

### admin.html 이 저장소에 없는 이유

정적 페이지에는 진짜 로그인을 붙일 수 없습니다. 비밀번호를 코드에 넣어도
소스 보기로 그대로 드러나므로 보안이 아니라 보안 흉내가 됩니다.

그래서 편집기는 **인증을 두지 않는 대신 배포하지 않는** 쪽을 골랐습니다.
`.gitignore` 로 저장소에서 빼고, 배포 워크플로에서도 공개 파일만 골라 올립니다.

**로컬 파일이 유일한 사본이므로 따로 백업해 두세요.**

## 배포

`main` 에 push 하면 GitHub Actions 가 `site/` 의 공개 파일만 모아
GitHub Pages 로 올립니다 (`.github/workflows/pages.yml`).

워크플로는 배포할 파일을 하나씩 지정합니다. 새 페이지를 추가하면
워크플로의 목록에도 넣어야 합니다.

## 알아 둘 것

### 폰트를 파일 안에 넣었습니다

한글 본문은 [Pretendard](https://github.com/orioncactus/pretendard) 를 쓰는데,
Google Fonts 에 없어서 **페이지에 쓰인 글자만 골라 서브셋한 뒤 인라인**했습니다.
덕분에 외부 요청 없이 뜨지만, 대신 이런 제약이 있습니다.

> **내용을 크게 바꾸면 폰트를 다시 구워야 합니다.**
> 서브셋에 없는 글자는 시스템 폰트로 폴백돼 한 문장 안에서 서체가 섞입니다.
> 현재 `index.html` 기준 한글 506자만 들어 있습니다.

다시 굽는 방법:

```bash
pip install fonttools brotli
# Pretendard 가변 웹폰트를 받아 페이지 문자로 서브셋한 뒤
# <style> 맨 앞의 @font-face 블록을 교체합니다.
```

### 서버가 없습니다

- **견적 문의 폼**은 메일 앱을 열어 내용을 채워 줍니다. `mailto:` 규격상 첨부파일은
  실을 수 없어 파일 목록만 넘깁니다. 실제 전송과 첨부가 필요하면
  `index.html` 의 `sendInquiry()` 한 곳만 바꾸면 됩니다.
- **상담 챗봇**은 화면과 흐름만 있습니다.
- **PALLET 데모**는 새로고침하면 처음 값으로 돌아갑니다.

### 공개 전에 바꿔야 하는 것

- [ ] `hello@forge.studio` → 실제 이메일 (`site-data` 의 `contact.email`)
- [ ] 사업자 정보 표시 (상호·대표자·사업자등록번호·주소·통신판매업 신고번호)
- [ ] 개인정보처리방침 — 문의 폼이 이름과 이메일을 수집합니다
- [ ] `og:image` — 없으면 링크 공유 시 썸네일이 뜨지 않습니다
- [ ] 폼 전송 엔드포인트

## 만들면서 정한 것

- **담금질 산화색**을 구조로 씁니다. 쇠가 달아오르며 지나는 색(회청 → 청 → 자 → 주 → 금)이
  진행 단계, 작업 강도, 배경 입자의 온도를 나타냅니다.
- **배경은 입자 물리**로 돌아갑니다. 커서가 지나가면 밀려났다 스프링으로 제자리에 돌아오고,
  밀려난 거리가 곧 열이 됩니다. 60fps 상한과 적응형 품질(프레임이 밀리면 알갱이를 솎음)이
  들어 있어 느린 기기에서도 끊기지 않습니다.
- **작업 카드 프리뷰**는 이미지가 아니라 제품 UI 를 그대로 그린 뒤 CSS 로 축소한 것입니다.
  데모를 고치면 프리뷰도 같이 고쳐집니다.
- **배경 움직임은 끌 수 있습니다.** 내비의 밝기 버튼 옆 토글로 입자와 마퀴를 멈춥니다.
  계속 흔들리는 화면에 멀미를 느끼는 사람이 있어서 넣었고, 선택은 기억됩니다.
  운영체제에서 이미 모션 최소화를 켜 둔 사람에게는 처음부터 꺼진 상태로 뜹니다.
